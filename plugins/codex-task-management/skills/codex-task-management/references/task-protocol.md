# 任务书与回执

任务书写进 issue description，回执写 issue comment。执行规则见 [SKILL.md](../SKILL.md)。

## 任务书（issue description）

```markdown
## 目标
<真实场景、预期行为和本轮完成点；说明是调查交付还是实施恢复，保留已明确的范围与授权>

## 对话归属
- 主控：<已指定的 thread ID；未指定则注明单任务，无需新设主控>
- 执行对话：<接单后记录正式 thread ID；创建中的临时 ID 不算已接单>

## 文件归属
- 允许修改：<文件或目录>（涉及跨目录辅助仓库时必须显式列出）
- 公共文件负责人：<负责人或 issue>
- 共享资源负责人：<浏览器、设备、账号等的唯一负责人或串行安排；没有则写无>

## 基线与依赖
- 主分支基线：<SHA 或分支>
- blocked_by：<issue 与原因 functional|serialization>
- 输入合同：<路径或链接>

## 交付要求
<功能、接口或数据；完成证据与下游使用方式。明确必要诊断及已批准局部修复的范围；新增安装、认证恢复、身份重建或外部写入仍按实际授权处理，不另加重复审批>

## required_checks
- <命令 1>
- <命令 2>

## 验证等级与证据
- 等级：<unit | snapshot | sandbox | live>
- 证据入口：<路径或 issue comment>
```

land.sh 合并前会逐条执行 `## required_checks` 小节内 `- ` 开头的命令（在交付 worktree 中），任何一条失败即中止合并且不计修正轮次。该小节每一行都会作为本地命令执行：只写验证命令，不放说明文字，不放带外部写入副作用的操作。无法用命令表达的检查写进交付要求，由验收人工判断。

## 回执（issue comment）

| 类型 | 时机 | 必含内容 |
| --- | --- | --- |
| 接单 | claim.sh 通过后自动写入 | 绑定 thread、workspace、worktree 路径与分支（脚本自动创建并写回 issue） |
| 派工核验 | 执行对话接单并开始工作后，由主控读回 | 正式 thread ID/可访问任务、执行者接单回执、实际 worktree/分支/HEAD、文件和共享资源归属、开始工作记录及核验时间；未齐全时记录实际缺口 |
| 方案送审 | 方案需要用户决策时 | 方案入口、关键取舍、缺失的授权或决策；同范围技术方案不逐次请批 |
| 阶段进展 | 有意义阶段结果时 | 产物、验收编号与证据、未完成项及正在执行的下一步 |
| 阻塞 | 某个必要步骤无法继续时 | 失败事实与脱敏证据、影响范围、已尝试动作、最后检查点、下一安全动作；确需用户或外部条件时写清谁需提供什么及恢复条件 |
| 交付待验收 | 转 in_review 时 | 冻结 SHA、逐项自查结果与验证等级、独立评审结论、遗留项 |

缺信息不等于等待用户；Agent 可在授权内查证的资料自行补齐，并沿用有效检查结果。回执复用原 issue comment；普通未纳入 Taskboard 的任务不因此新增台账。

派工核验补充脚本接单回执，不冒充脚本自动校验。创建中、只读交接、正式接单和已启动分别如实记录；只读交接写明旧绑定、接收对话、候选路径/指纹与未转移写入权。

交付待验收后 writer 停止修改候选；要改先退回 in_progress。文档审批或合并不阻断与其无依赖的已授权调查；交付回执明确当前通过范围，未验证实施合同仍是对应步骤的前置条件。

## landed 回执

land.sh 成功后自动追加：landed_sha、分支与方向、required_checks 逐条结果、用户批准说明与时间。issue 随之转 done，该回执即最终验收与合并凭证，不另写归档文档。
