# Codex 任务管理

通用任务协作规则在本 Skill 维护；项目 AGENTS.md 只补充项目事实、业务边界和指定入口。项目计划与当前状态留在项目内，不复制到本 Skill。使用现有 Codex 任务能力，不另建调度、消息、日志或任务历史系统。

## 入口与责任

- 先读项目规则、权威索引和自身任务卡，再核对实际运行者、人工等待状态、主机、绝对目录、分支、HEAD、未提交差异及产物。恢复聊天不能替代当前状态核验；新任务不默认继承旧聊天。派工、接单和恢复都核对实际 Skill 路径与内容指纹；跨主机缺失或版本不符时只暂停受影响工作，不静默沿用旧副本或复制密钥。
- 项目指定一个主控和一个权威索引，默认用保存项目的集成工作区与 `docs/tasks/INDEX.md`；下文以 `main` 指集成分支，项目明确约定优先。主控负责范围、依赖、派工、集成、审查和最终验收；模块自主细化已批准范围。切换主控前停止旧主控派工和索引写入。
- 小步骤留在当前任务。只有可独立分配、交付和验收的工作才拆模块；未经用户明确要求不创建用户侧独立任务，短期独立探索和评审可使用子 Agent。不重复启动已有运行者，不与模块同时修改其负责文件。
- 派工、建卡或回传时读取 [任务书与回执](references/task-protocol.md)。创建流程生成的 ID、主机和路径在返回后核验补齐，不能猜测。用户决定范围与授权；子任务继承父任务批准方案，改变合同、外部操作边界或验收目标时重新取得对应人工批准。

## 活跃记录与执行基线

- 未完成工作只维护权威索引和每个模块工作树内的一张任务卡，默认 `docs/tasks/<任务标识>.md`。索引仅主控写，保存定位、依赖、阶段、修正次数和待决策入口；卡仅对应 writer 写，保存批准范围、检查点、证据和下一步，不复制完整聊天或日志。工作树复制出的索引不具权威性。
- 在方案批准、有意义的阶段结果、阻塞、交接及本轮结束前更新必要记录，不为每条命令写报告。批准须能定位到具体范围和版本；换对话不改变任务身份、授权或历史计数。
- 派工记录批准的 main 基线及规则、合同的实际版本；未提交文件还需可读取原件与内容指纹。main 更新不会自动同步到其他工作树，HEAD 相同也不证明未提交内容相同。变化只暂停受影响工作，由主控协调重读和安全同步，保护未提交成果。
- 主控到索引指定主机与绝对路径读取真实任务卡、差异和产物；跨节点取不到原产物就标记证据待核验，不凭摘要验收。落盘不是远端备份；同步前核验目标节点的 Skill、运行时、权限和凭据依赖。

## 并行与有限评审

- 独立代码交付使用独立 `codex/` 分支和 worktree，每个工作树同一时间一个 writer；小步骤共用工作树。公共合同、重叠文件和共享配置明确负责人。worktree 只隔离代码，设备、会话、schema 及危险外部副作用按冲突资源串行；只读或合同明确允许并行的操作无需全局串行。
- 模块先核对实现、真实合同和必要外部事实，再形成方案。由同一名独立只读评审者先检查架构与正确性，通过后检查过度设计；项目指定评审 Skill 时按其顺序执行，否则使用现有独立评审能力，不自动安装依赖。两项无阻断且人工方案评审通过后才编码。已明确批准的同一范围不重复询问；普通小改动不因本 Skill 自动升级为模块方案流程。
- 仅直接阻断当前验收的 P0/P1 或关键证据缺口必须修复；P2/P3 不要求清零，复杂度检查不代替正确性审查。非阻断问题留待后续范围决定，不自动扩展任务。
- 方案、交付各允许首次评审后最多两轮自动修正，字段为 `plan_fix_rounds`、`delivery_fix_rounds`。主控每次派修前在权威索引回读、加一并确认保存；两项方案评审共用方案计数。只有从未评审的新父任务从 0 开始；接管、拆分旧范围、换版本、评审者或对话均不清零。旧计数须恢复，不能证明剩余额度则交人工裁决；达到 2 仍有阻断便停止自动派修，无阻断可交付。
- 实现后由一名独立代码审查者检查最终差异。审后改动仅补查受影响内容，结论必须覆盖最终版本，不反复重跑无关方案审查。纯说明文档做一致性、链接和差异检查；只补路径等元数据检查差异即可。AGENTS、Skill 或可执行配置改变行为时补验相关加载/执行，静态检查不冒充运行成功。

## 冻结、人工验收与集成

1. 模块完成约定的合并前检查、独立审查及适用的部署/加载验证，冻结候选与证据。未提交候选须包含完整可审差异、新增文件及内容指纹。验收位置独立于开发位置；依赖 main 的部署、加载或业务回读列为合并后条目，需要环境而缺失时标待验证，确实无需该项才标不适用。
2. 需要人工验收时，在原模块对话展示冻结版本、已通过条目、结果入口及留到合并后的条目。不通过就在原任务按人工反馈继续迭代、重新冻结并补查受影响内容，保留身份和计数；超过自动额度后按具体人工指令推进，不解释为无限自动重试。人工通过须记录可定位的原文、时间、候选及验收编号；有效确认不重复索取。
3. 模块使用原生 `send_message_to_thread` 向任务书中已核验的主控 ID/主机发送“交付待验收”回执，注明“人工验收通过，待合并”；无需人工验收或合并时明确不适用。同一候选的同一结果只通知一次。交付回执不等于主控最终验收，不自行清理成果。
4. 主控读回原始证据、人工确认、实际冻结候选及独立审查覆盖范围，核对最新 main 和提交、合并、推送各自授权。唯一集成者按依赖逐个合并并回读 main，完成最小相关检查及约定的合并后部署/加载、业务样本与精确读回。分别说明代码验收、main 集成、部署/加载、真实业务验收，未完成或不适用须明确。
5. 回传交付后 writer 停止改候选。需要修改时，先取得主控暂停收取的确认，再解除冻结；受影响的旧审查和验收失效，不边改边合并。合并冲突或行为变化须补查，影响人工确认内容则回原模块补验；依赖 main 的人工验收也在原模块完成。
6. 全部必要验收通过后标记“验收通过，待收尾”，结束该模块的业务迭代，只继续下节复盘和清理。缺必要验收或 Git 授权时保留成果和待办，不把局部通过报成全部完成。

进度查询使用原生读取/等待接口，不发“继续”消息代替查询。原生工具缺失只阻塞相应动作；本轮结束不等于开启持续监控，需要后台跟进时依据用户授权使用原生自动化。外部写入不因派工或验收自动获批，遵守项目的目标、前置状态与读回边界；结果不明先精确回读，禁止盲重试。

## Skill 交付时的加载验收

仅在交付本身需要 Skill 时适用，不要求每个模块包装为 Skill。用户指定安装范围优先；项目模块候选默认放在其工作树的 `.agents/skills/<skill-name>/SKILL.md`，资源一起冻结且受 Git 跟踪，复用已有实现而不搬迁代码。候选验证不先覆盖 main 或用户全局版本；用户级安装需对应需求与授权。

实际核验运行时发现、选中的目录、内容指纹和按批准样本执行的调用结果。读取文件、目录存在或技能名称可见只证明部分状态，不证明执行；同名 Skill 不假定覆盖，新版本不能用旧上下文冒充。未发现更新先核验加载状态并保存检查点，再按宿主机制处理。

主控合入 main 即完成项目 Skill 的版本持久化，无需再复制一套。清理工作树前核验 main 中的引用、依赖、实际发现与调用，不能遗留指向待删除工作树的路径；验证不扩大业务权限。

## 完成后的复盘与清理

1. 在原模块对话简要提炼复用经验，优先更新现有 Skill、项目规则或适用的全局规则；没有明确复用价值就不新增文件，不另写复盘报告。更新仍须符合现有授权，项目专属事实不写入全局。
2. 主控就地更新 README 对应功能的已实现能力、使用入口和实际限制，不追加任务流水或长日志。未完成事项先移交必要事实、依赖、授权及适用历史计数，不能因删卡重置额度。
3. 核对精确路径、引用与恢复方式后，删除已完成任务卡、过程计划/评审、一次性脚本/日志/快照及无用恢复物，修正失效链接。代码、必要测试、现行合同、运行恢复和未完成工作仍依赖的资料保留；旧文档独有的有效结论先提炼。清理专用短期副本读回后移除，不新建永久任务归档目录或 ZIP，不重写 Git 历史、不导出聊天另存一份。
4. 核验实现、README 和必要沉淀已按授权持久化且无活动 writer，再清理专属工作树及已集成分支，通过原生归档工具归档模块对话并读回。未验收或未安全保存的工作树保持置顶，不提前归档清理；已完成模块不接新业务，主控继续协调。收取、清理与归档在同轮完成，不等用户另行提醒；必要授权或能力缺失时保持待收尾并说明具体缺项。

后续调整通用协作规则只修改本 Skill 及相关模板；项目只维护自己的边界和入口。验收分别说明静态结构、实际发现/调用和真实模块协作流程，不能互相替代。

本 Skill 的维护源码位于 [kinsolee/agent-skills](https://github.com/kinsolee/agent-skills/tree/main/plugins/codex-task-management)。修改本 Skill 或引用资源时，先读取源码仓库根目录的 `AGENTS.md`，按该仓库约定验证、提交和推送；安装缓存不作为源码修改入口。
